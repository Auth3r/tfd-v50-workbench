# 00 · 上手指南（给新加入的成员）

这个仓库是 TFD 离线核心工程的**全部源码**。目标只有一句话：**不依赖 V50 外壳和任何注入，自己应答真实客户端。**

---

## 1. 环境准备（只做一次）

| 需要 | 说明 |
|---|---|
| Rust 1.89+ | `rustc --version` 应 ≥ 1.89（当前用的是 1.100） |
| Windows SDK / CRT 导入库 | 约 700 MB，**不进仓库**（体积大且属第三方） |
| 网络/代理 | 首次下载库文件需要；`http://127.0.0.1:7890` 是常用代理 |

一次性准备：在仓库根执行 `setup-build-libraries.ps1`（或 `download-build-libraries.cjs`），它会生成 `.build-tools/lib`。

> **注意**：`.cargo/config.toml` 里把 `LIB` 强制指向 `.build-tools/lib`，并用 `rust-lld` + `+crt-static`。**没有这个目录时，代码能编译但会在链接阶段失败**（报 `linking with rust-lld failed`）。这不是代码问题。若你已有 Visual Studio Build Tools，可改用系统 CRT，见 §5。

## 2. 跑起来

## 3. 目录在哪

| 路径 | 是什么 |
|---|---|
| `rust/` | 核心实现。`v50_payload.rs`（报到层）、`v50_login.rs`（登录 body）、`v50_save.rs`（存档）、`v50_codec.rs` / `v50_handlers.rs` / `v50_schema.rs`（协议与结构） |
| `tests/` | 测试。`fixtures/` 里是**真实抓包字节**，不是编码器反算的 |
| `docs/` | 报告与判据。`docs/evidence/` 有溯源清单 |
| `docs/evidence/frames-154.json` | 154 帧整帧真值（帧头 + 载荷 + body），**回归用的基准** |
| `docs/evidence/v50_payload/provenance.json` | 夹具溯源：源文件 sha256 + 抓包行号锚定 |

## 4. 几条硬规矩

1. **不许用“自编码→自解码相等”当交付**。自洽证明不了真相。
2. **夹具必须是真值**。新夹具要写清来源（文件、行号或哈希），否则不接收。
3. **判据不许为通过而改**。对不上就写 UNKNOWN，写清“第几条、哪个字段、期望、实得”。
4. **每块活都要带负对照**：改一个字节，必须报出恰好一处差异。
5. 二进制、存档原件、抓包原件**不进仓库**。

## 5. 若链接失败

没有 `.build-tools/lib` 但本机有 VS Build Tools 时，可以临时覆盖配置：

```powershell
cargo test --config 'target.x86_64-pc-windows-msvc.linker="link.exe"' --config 'target.x86_64-pc-windows-msvc.rustflags=[]'
```

有其他机器上跑通的同学，把命令补到这里。

## 6. 推荐模型与推理强度

用 AI 辅助时：**GPT-6.2 Astra，推理强度拉满**。理由：这些活全是“对真值逐字节”，失败方式是安静地错位而不是报错；中等档模型很容易给出“看起来对”的结论。
