# 01 · 内容包拆解（`content.sealed`）

**目标**：把内容包读出来，让核心里有“角色、装备、任务表”这些真实数据。

---

## 1. 文件在哪

```
E:\第二后裔\TFD发布端V50\TFD发布端V50\unpacked\assets\content.sealed
```

大小 22,001,501 B（约 21.0 MB），修改时间 2026-11-19。**只读，不要改。**

## 2. 已经确认的结构（别重新摸索，直接用）

```
[13 B]  magic  "TFD-SEALED-V1"
[ 1 B]  0x00
[ 4 B]  u32 LE 索引长度 = 64,834
[64,834 B] 明文 JSON 索引
[剩余   ] 块区（各资产的压缩数据，按索引里的 offset 拼起来）
```

索引 JSON 顶层：`{"payload": {...}, "signature": {...}}`，`payload` 下有 `entries / format / info / product / source_sha256`。

`payload.entries` 是 **412 条**，每条形如：

```json
"asset/assets/client-labels-zh.json": {
  "offset": 0, "size": 1003245, "plain_size": 6346825,
  "sha256": "6cd8c197b3e4acff30f215d090e686f612a1ab3e14037f30405d4883f7b657af"
}
```

- `size` = 块区里占的字节数（压缩后）
- `plain_size` = 解压后应有的大小
- `sha256` = **解压后明文的哈希** ← 这是验收用的真值，等于 412 个考卷答案

已看过的大件：`client-labels-zh.json`（明文 6.3 MB）、`support-catalog.json`（3.4 MB）、`full-profile-catalog.json`、`full-gear-catalog.json`、`switching-catalog.json`。

## 3. 还没解决的：块区是什么编码

已验证**排除**的四种（用第一条记录的 `sha256` 判定，全部不符）：

- raw deflate（`zlib.decompress(blob, -15)`）
- zlib（带 zlib 头）
- bz2
- lzma

块区首条前 16 字节：`c9 15 08 f6 88 31 11 dd 21 9c c6 e7 82 48 f9 dc`（看不出标准容器头）。

**要做的**：找出块区的解压/解码方式。

**思路（按成本排）**：

1. 用 `plain_size / size ≈ 6.33` 这个压缩比反推：像文本 JSON 的 deflate/oodle 级别压缩，不像加密。
2. 试 LZ4（block 与 frame 两种）、Oodle（TFD 是 Unreal，客户端可能内置 `oo2core` 实现）、以及“先解密再解压”的组合。
3. 从客户端里找解包代码：`M1-Win64-Shipping.exe` 或 `client.dll` 里搜 `TFD-SEALED-V1` 字符串，定位读取函数，看它调用哪个解压库。
4. 索引里有 `signature`，先看清它签的是索引还是块区——如果是块区签名，说明**不能改内容**，只能读。

**判据（硬）**：任取一块，解码结果与 `plain_size` 长度相同且 `sha256` 与索引声明值相等 → 该块判绿。**至少要覆盖 10 块不同类型**才算这条路径可能通用；412 条全绿才叫完成。

**失败也要报**：解不开就写清“试过哪几种、分别报什么错、首块字节特征”，这本身就是进展。

## 4. 交付

- 一个能跑的脚本：`sealed_extract.py input.sealed outdir/`，支持 `--check` 只校验不落盘。
- 一份记录：命令 + 完整输出 + 412 条校验结果（绿/红各多少）。
- 一份 `UNKNOWN.md`：解不开的块、试过的方法、下一步猜测。

- 不要用“长度对上”当绿，必须 `sha256` 对上。
