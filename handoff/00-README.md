# 交接包 · 00-README

**这是什么**：TFD 离线工作台（Build 26722146）的**主干交接包**。目标只有一个——把"让成员双击能进游戏、能选角、能进世界"这条最小闭环之外的所有纯离线工作，整块交出去，让接手的执行方不需要理解本项目历史，也能独立开工并自证完成。

**不是什么**：不是完整方案，不含内容页语义、不含 21 个集合域的全量实现、不含客户端桥的后续演进。这些都还在做。

## 2. 阶段定义（这次只要主干）

- **P0 主干**：构建基线、帧层、登录握手、存档映射、账号快照编码、账号↔客户端对齐、选角进世界、任务只读、起停取证。
  做到这里，成员就可以开始干活，后面再迭代。
- **P1**：集合域（21 个 collection / 8 mutations / 2 oneway）逐域点亮。
- **P2**：内容页 `content.sealed` 语义（当前最大空白，不承诺时间）。

---

## 3. 归属分界（唯一标准）

判据是**"要不要开游戏看结果"**：

- **不用开游戏的 → 交出去**：M00 构建、M01a body 解码、M02 登录握手、M03 存档映射、M04 快照编码、M07 离线部分、M08 集合域。
- **必须上机看结果的 → 留在主开发侧**：M01b 帧头分帧、M05 账号对齐、M06 进世界、M09 内容页、M10 桥、M11 起停取证。

判断一条活能不能交出去，只看一件事：**它的验收判据能不能在本地跑出来。** 跑不出来的一律不交。

---

## 4. 当前状态（一句话）

服务端能生成 36 条角色，并随 `1004` 应答出网；客户端原生读数仍是 0，走的是创角。卡点在**"编码 ↔ 客户端解析"这一层对齐**，不在数据有没有。现在能进世界靠的是 57 秒的 `character-progress` 旁路，不是原生流程。

---

## 5. 怎么用

1. 先看 `02-模块表.xlsx` 的 **01-模块表**，认领一行，读它的"可复用资产"和"验收判据"。
2. 用 `01-资产清单.json` 的 sha256 核对拿到的资产是不是同一份版本——对不上就停下来说，不要凭文件名开工。
3. 自测输入用 `03-考卷样本.json`（注意：`1010` / `1012` / `1004` 三条的 `res_hex` 带 `res_err`，是被截断的，不能当完整应答用）。
4. 动手前过一遍 `04-边界与禁改清单.md`。

---

## 6. 交付怎么算完成

- 判据在本地能跑绿，附上跑的命令与输出，就算完成。
- **自洽不等于可用**：M04 的"自编码再自解码逐项相等"只证明内部一致，不证明客户端认。这一条要在文档里写清楚，不要当成 A 通了。
- 做不到、或判据本身不成立，就如实标"未完成"并说明卡在哪，不要降低判据换一个绿。

---

## 7. 一条硬约束

本包只用于本机离线研发验证：**不发布、不分发、不上传资产、不对外提供下载**。这条写进了 `04-边界与禁改清单.md`，作为接手的边界条件。
