# TFD V50 新版客户端（Build 26722146）UI 黑屏定位报告

- 日期：2026-11-20（现场最后一轮 run `20261119T202607-1978ef`）
- 目标：让新版客户端（sha 前缀 `a601a30d`）在 V50 免授权发布端下把登录页/大厅页真正显示出来
- 路线：按用户指定，**只走第 1 条（IDA 静态定位页面字段 → 修 UI）**；不碰第 2 条（绕开 UI 直接构造 1006）
- 结论：**页面机制已打通到底层（`showLogin` 从"报错"变成"成功建页"），但页控件从未被合成到屏幕，画面依旧纯黑。** 本轮把"黑屏"从一个模糊现象，收敛成了一个有明确下一步的具体缺口。

## 一、一句话结论

新版客户端的 UI 系统是**活的**（控件池峰值 250,717 个对象、页面容器存在、GPU 3D 占用 42%~73% 持续渲染），但**页面容器的"当前页"句柄一直是 0**，取当前页函数 `0x4850BB0` 返回 0，切页函数 `0x4850220` 在正常启动流程里**一次都没被调用过** —— 也就是"没有任何页面被 show 出来"，渲染循环画出来的就是纯黑。

旧桥那套"扫控件池找大厅 → 调 showLogin"的自动补救链在新版**全线失效**，原因是三个偏移/映射同时错了。本轮已把它们逐个改正并在实机上验证，其中最后一步（**把 native 调用搬到游戏线程**）让 `showLogin` 第一次真正成功。

## 二、静态分析（IDA，新版 base `0x140000000`，IDB `C:\tfdwork\new.i64`）

### 2.1 新版页面字段是 `+0x738`，不是旧桥的 `+0x748`

`sub_144AA36B0`（旧 RVA `0x49cdbf0` → 新 `0x4aa36b0`，全函数只有 97 字节）：

```
mov rcx,[rcx+720h]        ; 取页面容器
test rcx,rcx / jz ret0
cmp  [rbx+738h],edi       ; 比较当前页
mov  [rbx+738h],edi       ; ★ 写当前页 —— 这就是新版页面字段
call sub_144850220        ; 真正"显示第 N 页"
jmp  sub_144850BB0        ; 返回当前页控件
```

旧桥全程读 `+0x748`（新版该处是别的字段，读出来是垃圾值），所以 `prepareTitle` 里 `page===3` / `page===-1` 的判断永远不成立，`showLogin` 永远不会被调用。**这一条直接解释了"页面切换钩子从未触发"。**

### 2.2 旧桥的 `lobbyClass()` 在新版指错了类

`0x38e1390`（旧 `0x38ff0c0` 的映射目标）反汇编是通过 `sub_1451D1180` 按名字取类的包装，类名字面量是 **`M1UIDropContainerMarker`**（size `0x788`），与大厅无关。这就是 v16 在 2 万控件里"类链命中 0"的根因。

### 2.3 真正的页面类名（同一类取值包装，读的是字符串字面量）

| 地址 | 类名 | 类大小 | 类缓存全局 |
|---|---|---|---|
| `0x394d560` | **`M1UILogin`** | `0x7D8` | `base+0xbcd1e58` |
| `0x3913f80` | **`M1UIGameStartMenu`** | `0x7B8` | `base+0xbccf978` |
| `0x38e1390` | `M1UIDropContainerMarker` | `0x788` | `base+0xbccd760` |

→ 页面号语义确认：**page 3 = 登录页，page 4 = 角色选择/开始菜单页**。

### 2.4 页面容器布局

| 偏移 | 语义 |
|---|---|
| `+0x720` | 页面数组指针（条目 48 字节） |
| `+0x728` | 页数（实测 5） |
| `+0x7B8` / `+0x7BC` | **当前页的 (索引 / 序列号) 句柄** —— 黑屏的直接证据就是这两个一直为 0 |
| `+0x7E0` | 被 `sub_144850480` 置 -1 |

`sub_144850220(container, pageIdx)` = 显示某页；`sub_144850BB0(container)` = 用句柄回池取当前页控件（全程序 165 处调用）。

### 2.5 `showLogin`

`sub_144AA2CD0(host, ticket)`：`[host+0x730]` 是对话框子控件；走到 `0x4aa2fe1` 时 `mov edx,3; call sub_144AA36B0` 切 page 3，再校验页控件的类链是 `M1UILogin`。`sub_144AA3240` 同理切 page 4 校验 `M1UIGameStartMenu`。

### v26 关键读数（原文）

```
before       n=5 idx=0      ser=0     cur=0x0          ← 没有当前页
afterLogin   n=5 idx=251099 ser=24942 cur=0xd9ed3740   ← showLogin 建出了 page3 控件

```

**这是本轮最硬的进展**：`showLogin` 不再是"报错"，而是**真的把登录页建出来、并挂进了页面容器**。

### 3.1 为什么之前一直失败（机制级）

1. **线程错**：Frida 的 `setInterval` 跑在 Frida 自己的线程上，UE 的 UMG 代码要在**游戏线程**跑。v23 的 `Error: system error` 和 v21 的 `0xC0000005` 本质都是这个 —— 不是偏移错，是**调用线程非法**。搬到 `0x449d540` 的 onLeave（游戏线程）后，同一个函数、同一个宿主，立刻成功。
2. **宿主唯一且稳定**：每次运行地址随机（`0x36d221c0` / `0xecdb21c0` / `0x355e21c0` / `0x37b121c0`），但**用"`obj+0x720 == 容器"反查，永远只有 1 个，page 恒 -1**。这条路可以固定下来，不用再扫全池找"大厅"。
3. **`M1UILogin` 类缓存早期为 NULL 是正常的**：页控件是"按需创建"，登录页没被 show 之前根本不存在。所以"类缓存 NULL"不能当成"类错了"的证据。

## 四、还没解决的问题：页控件建出来了，但没上屏

v26 之后，页面容器里已经有真实页控件指针（`0xd9ed3740`），`0x4850BB0` 也能取到它，但 **DXGI 抓图（3840×2160 → 裁窗口 868×517）仍然是 100% 纯黑**（`nonblack 21133/28210`，非黑部分全是窗口外桌面）。

因此缺口已经从"页面切不过去"变成了**"页控件没接到可见的 widget 树上 / 没被合成"**。可能的三种情况，按可能性排序：

1. **没挂 viewport**：`showLogin` 只把页控件登记进容器，正常流程另有一段"把页控件 AddToViewport / AddChild 到 UI 根"的调用，我们没触发（静态上 `0x4AA2CD0` 里 `0x4850220` 之后还有分支没走完）。
2. **UI 根本身就没建**：整个 Slate/UMG 的 viewport 层缺失，250k 控件是一个"孤岛树"，渲染器拿不到根 widget。
3. **可见性/层级字段为 0**：控件存在但 `Visibility=Collapsed` 或 render opacity 0，或不在 `visible widget` 链上。

## 五、下一步（按性价比排序，建议照这个顺序做）

1. **验类名**（10 分钟）：读 `cur=0xd9ed3740` 的对象头 `+0x10` 类型指针，再读类型的 UClass 名字，确认它确实是 `M1UILogin`。这一步能把"我们建对了吗"变成硬事实。
2. **补 viewport 挂载**（核心）：在 `0x4AA2CD0` 的全路径里找 `0x4850220` **之后**的调用（IDE 反汇编已存在 `C:\tfdwork\page_funcs.txt`），看它是否调了某个 `AddToViewport` / `AddWidget` / `SetContent`；找到就在游戏线程补调一次。
3. **查 UI 根**：定位 game viewport client 的 widget 指针（UE 里是 `UGameViewportClient::AddViewportWidgetContent` 那一族），读它当前内容是不是空。若空 → 说明整条 UI 根链没建，得从"创建 UI 根"入手，而不是继续在页容器里折腾。
4. **查可见性**：读 `cur` 控件父链与 `Visibility` / `RenderOpacity` 字段，排除"建了但藏起来"。
5. 顺带收尾（不影响主线）：新版 mastery 偏移（旧读法 `+0x80/+0x88` 恒 0，真值 14/350010）仍未定位；桥内还有约 28 个地址 / 52 处 vtable 比较未迁移；`+0xB8` 读到 35 而服务端发 36，差 1 的语义未证实。
