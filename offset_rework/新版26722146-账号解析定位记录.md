# Build 26722146：账号/角色列表丢失 定位记录（2026-11-20 凌晨）

## 一句话结论

旧客户端（build 26263743）吃同一份发包 → 36 个角色正常；
新客户端（build 26722146）吃同一份发包 → `CharacterList` 恒为 0。
两份客户端的报文 schema（字段名、顺序、类型 id、消息 id、结构体大小）**逐项一致**，所以不是 schema 差异，是新版客户端对这条账号响应的处理链路不同。

| 主测 | 新客户端 + 迁移桥 + 36 char，手动创角提交 | 服务端 `initial_descendant_saved {created: False}` → 客户端 `NE:0100 与游戏服务器断开` |

## 已排除

1. 服务端空账号：`Store.resolve_session/list_characters/selected_character/load_mastery` 全部有值，`account_snapshot` 的 `CharacterList` 是 `list[36]`。
2. 字段改名/数量变化：`M1AccountSimpleInfo` 两版均 size=0x118、35 字段、id=0x4500000023；`M1CharacterSimpleInfo` 均 size=0x50、8 字段、id=0x4500000004。
3. 字段类型宽度变化：`CreatedTime` 两版都是 0x19（64 位）；`CombatPower/PlayTime/SelectedCharacter` 都是 0x04（32 位）；`CharacterTid` 0x19；`Level/MaxLevel/SelectedLoadoutSlotIndex/EigenFactorLevel` 0x03；`Favorites` 0x4c。
4. 数值大小导致变长：把 `CreatedTime` 撑到 >2^32 强制 64 位，`character_count` 仍为 0（编码器按 schema 固定宽度写）。
5. 角色条目字段增删：新版角色结构只有 8 个字段（`Uid/CharacterTid/Level/MaxLevel/EigenFactorLevel/Favorites/SelectedLoadoutSlotIndex/Customizes`），我们额外发的 `CustomizeOptions/Paints` 属于旧版可忽略的多余字段；删字段会直接 `0xC0000005` 崩溃或 `connection_rejected`，说明强校验。
6. 请求号不同：新版与旧版登录阶段发的 procedure 完全一致（1003/1004/1010/1012/2010/30001/3452；`30004` 是 5 秒心跳，不是每角色请求）。

## 现场结构（新版）

- 引擎侧账号对象（`0x44a5370` 的 rdi）：`+0x40/+0x48` = WearingList（ptr/num=4，读对了）；`+0xB0/+0xB8` = 角色数组（ptr/num=0）。
- `+0x50` 之后整片为 0，说明客户端侧在 WearingList 之后就没有可用数据。
