# 黑屏根因排查（2026-11-20 12:15）

## 结论先说

黑屏不是 UI 代码问题，也不是分辨率/全屏问题，也不是我加的 3801 补丁问题（已 A/B 回退验证）。

**真正的事实：客户端这次根本没走到"创建标题界面"那一步** —— 我们钩的标题创建等待函数 `0x4aa94a0` 一次都没被调用。

## 证据链

### 1. 成功局（run `20261120T032428-1d6047`，本地 11:24）

```
t=24.201  native_title_creation_error   description="Error: access violation accessing 0xffffffffffffffff"
t=24.201  native_account_loaded          character_count=0  creation_required=true
t=24.217  request 10000  →  response 10000     ← 标题页在这一刻创建
t=75.286  native_creation_confirm_clicked       ← 用户点创角
```

- `native_title_creation_error` 来自 `0x4aa94a0` 的 onEnter（bridge 第 423 行 catch），**说明那个函数被调用了**。
- 紧接着客户端发出 `10000` 请求，UI 出现。

### 2. 黑屏局（`20261120T040451-a04e54` 12:04、`20261120T040756-4f5b4f` 12:07 回退补丁后、`20261120T041040-f974fc` 12:10 v29 打点、`20261120T041328-3583ac` 12:13 v30 采样）

```
t=23.788  native_account_loaded  character_count=0  creation_required=true
（之后只有 keepalive，没有 request 10000，也没有任何 title_creation 事件）
```

- v29 打点：`owner_enter` 事件数百条，**`hasFrame` 全为 false** → `waits` 栈始终为空 → `0x4aa94a0` 从未进入。
- v30 调用栈采样：`0x4acf6c0` 被高频调用，栈集中在 `0x4acfcea < 0x4acc057 < 0x6b0708c < 0x3cb338e < 0x53cb78d ...`，属 UI 遍历/布局的正常调用，但**没有一条经过标题创建路径**。

### 3. 已排除的假设

| 假设 | 检验方式 | 结果 |
|---|---|---|
| 3801 补丁（`patch_v50.py`）破坏启动 | `git checkout -- patch_v50.py` 回退后重跑 | 仍黑屏，且同样无 `10000` |
| v28 摘掉标题接管导致 | 12:02 用 v28 | 仍黑屏（当时结论） |

| 角色数据被读成 0 条 | 对比成功局 | 成功局也是 `character_count=0`，不是差异点 |

## 当前唯一差异

成功局：`0x4aa94a0` 被进入（并抛异常）；
黑屏局：`0x4aa94a0` 从未被进入。

两者镜像、补丁、桥模板、账号、存档一致 ⇒ 差异在**客户端运行期状态**，不在代码。

## 待验证方向（尚未执行，需确认）

1. **存档/会话残留**：11:24 那局创角成功并进过阿尔比恩（有 `InitialDefaultPlayerSetId=106100003` 的角色 + 世界会话痕迹）。客户端可能在启动后走了"续接会话"分支而跳过标题页 → 用空档账号或 `pre-graft` 备份对比验证（不碰用户真档）。
2. **重复强杀导致的 GPU/DXGI 残留**：连续多次 `Stop-Process` 后重新起局；对照一次冷启动（重启客户端与 `explorer` 之外的渲染状态）。

两项都不改代码，只做对照实验。
