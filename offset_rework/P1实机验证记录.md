## 这一关是怎么解开的（技术路径）

1. **旧/新布局差分**（关键）：用同一支字段探针分别跑旧版与新版，得到
   ```
   OLD 0x6e0..0x7a0  ==  NEW 0x6f0..0x7b0     （控件成员整块 +0x10）
   OLD 0x7a0 = 非空(守卫通过) → NEW 0x7b0 = 非空
   ```
   → 守卫成员从 `+0x7a0` 漂到 `+0x7b0`，`0x738→0x748`、`0x720→0x730`、票根四字段各 +0x10。
   应用后：守卫通过，`prepareTitle` 每秒真的被调用了。

2. **类比对在核心里失效**：`prepareTitle` 要在 GUObjectArray 里按"类深度 6 + 父链"筛出目标控件。
   ```
   NEW: count 241232, klass 0x181b2ec0, depth 6 → 候选 0 个
   OLD: count 236730, klass 0x18b81a80, depth 6 → 候选 3 个
   ```
   tick 对象的类深度只有 3（它是 component，不是 widget），说明扫描筛选条件在新版整圈落空。

3. **绕过而不硬碰**：发现 `login(component, ticket)` 只需要 component——就是 tick 那个对象，
   与"找不到的控件"无关。于是直接从 tick 里调原生登录入口（`0x449fe10`，已有钩子把 ticket 换成本地票）：
   ```js
   launcherAuthentication = true;
   login(obj, ticket);
   launcherAuthentication = false;
   ```
   → 第 22.99 秒连接建立。**这就是突破点。**
