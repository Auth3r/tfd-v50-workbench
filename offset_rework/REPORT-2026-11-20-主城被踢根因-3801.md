## 二、与 02:16 那局完全相同

02:16（run `20261119T181615`）同样在 `20000` 聚合链的**最后一条 `3801`（request_id 24）**被 `truncated payload` 拒掉。
也就是说：**不是“没有角色存档”，而是同一个包格式缺陷**，两次都卡在同一条。

## 三、3801 是什么

`unpacked\assets\network-expansion.json` 里明确：

```
"3801": "JumpingPeriodVaild"
```

客户端进入主城时会问服务端“跳级活动是否有效”。它的应答结构（同文件 schema）：

```
M1Response_JumpingPeriodVaild
  size = 4, alignment = 4
  fields:
    Notification : i32 @ offset 0     (flags 30)
```

**客户端要求恰好 4 字节（一个 i32 `Notification`）。**
服务端现在返回的字节数不足 4（或为空），客户端反序列化即报 “truncated payload”，
随即 `connection_rejected` 把连接断掉 —— 表现为“进主城被踢回主界面”。

对照：同批其它子命令（2201/123/3100/3400/1558/124/3201/1702/1705/1708/3651）全部 `response ... duration_ms` 正常返回，
只有 3801 这一条在 `response` 之前就被判坏包，说明**只有它的应答体长度不对**。
