# 第四批 UNKNOWN 清单

所有位置均从 04 的 dec_hex 第一个字节按 0 计，范围采用左闭右开。ZIP 内 03 的偏移是原生成员偏移。

| 关卡 / 项目 | 已知与缺口 | 继续需要的依据 |
|---|---|---|
| G1 工单目标 | 01 同时指定 seq 30/38、49852 B 和 proc 1004。两条指定出向帧的外层过程号均为 1400。包内 seq 14/22 的外层过程号才是 1004。 | 工单方指定采用两个真实 1004 应答，或确认目标为 1400 内的另一个账号子结构。 |
| G1 段起点、终点、段长和字段数 | 在 seq 30/38 的偏移 30 都能读到唯一的 demo。[28,35) 的 7 B 与 06 的 1004 样本前缀相同。第 8 B 已不同。整条帧长已知，内层段长未知。03 的 280 B 是原生结构大小，不能用它截出序列化段。 | 若保留 1400，请给出同一过程的父结构字段顺序、子段长度或经核验的同帧切片。单个字符串不能定位结束边界。 |
| G2 Uid / CharacterTid / Level / SelectedCharacter | G1 输入归属未裁定。SQLite 行比较执行了 0 条，成功和失败的角色行数均无实测值。 | 先通过 G1，再独立解出行和选中项，对照 05。 |
| G3 单行字段 | 缺经 G2 对账的线上记录。03 的原生成员偏移可读，但不能直接填入线上偏移列。 | G2 验收通过后的单行切片、字段取值和 SQLite 对账结果。 |
| G4 原字节相等性 | 已比较 RPC 参考样本，尚未从快照编码账号段，G4 执行了 0 次字节比对。 | G1 确定原段，G2/G3 确定结构，再比较编码字节。 |

脚本目前可复现包内 07、RPC 头及 G1 的证据。用 `--check` 在当前包上退出 3。指定 G2、G3 或 G4 时只复核前置并退出 4。角色解码器和账号段编码器尚未产出。脚本里的哈希是本次收到的版本指纹，ZIP 未另外附有发布方签署的清单。
