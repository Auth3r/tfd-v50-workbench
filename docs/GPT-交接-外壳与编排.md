# 交接 · 外壳与启动编排（接口版）

读者：`F:\Codex\TFD\rewrite` / `F:\Codex\tfd-offline-2` 的作者
项目性质：**本机离线测试工作台**。游戏本体来自用户已安装的客户端，不做分发；替换的对象是我们自己使用的第三方启动器的**界面层**。

**阅读顺序**：先 `GPT-交接-SYNC.md`（连接与启动链，管“能不能进游戏”），再本文件（界面与编排，管“谁来做 UI”）。

---

## 0. 一句话

界面层可以完全自研。启动编排需要沿用仓库里**已经跑通的那套本地初始化**，不要重新实现；游戏运行时组件（`unpacked/client.dll` 等）继续使用。

---

## 1. 三层结构

| 层 | 归属 | 本次是否更换 |
|---|---|---|
| 界面 / 编排（窗口、按钮、日志、启动顺序） | 自研 | **换掉** |
| 本地运行初始化（凭据、会话、数据目录准备） | 本仓库已有实现 | **复用，不改** |
| 游戏运行时组件（`client.dll` / `python314.dll` / 运行时依赖目录 / `assets`） | 继续使用 | 不动 |

原则：**上层换、中层复用、底层不动。**

## 2. 两个实现形态（B1 / B2）

### B1（有把握，约 1 天）

```
<自研壳>.py
  ├─ 复用仓库现有初始化（见 §3 的入口，不要重写）
  ├─ 拉起运行时宿主进程，主窗立即隐藏（SW_HIDE / 最小化）
  ├─ 启动后 3 秒内枚举顶层窗口，非本壳窗口一律关闭（PostMessageW WM_CLOSE）
  ├─ 读 client.txt → 校验客户端 exe 存在
  ├─ 桥走 bridge_override.txt → offset_rework/old_bridge_v30_bt.js
  └─ 只做四件事：启动 / 停止 / 看日志 / 退出
```

代价：后台仍有一个无窗口的宿主进程。**这是目前唯一有把握的形态。**

### B2（未验证）

不保留宿主进程，`sys.path` 指向 `unpacked` 直接导入其中的模块。

风险由我们承担说明：`client.dll` 是 Nuitka 编译的**主程序模块**，通常不能被外部 Python 进程按普通模块导入。**这条路径没有验证过，失败就退回 B1，不要在这里花时间。**

## 3. 接口约定

自研壳只需要对接三个入口，具体实现直接读仓库现有文件，**不要在文档层面重新推导**：

| 入口 | 职责 | 位置 |
|---|---|---|
| `init(cfg)` | 准备数据目录、会话、运行时配置 | 仓库现有初始化包内 |
| `run(cfg, stop, visible)` | 启动运行时并阻塞到退出 | 同上 |
| `client_path()` | 解析并校验客户端 exe | `<RUNTIME>\client.txt` |

约定：

1. `visible=True` 是我们验证过的取值；`False` 是否等价“无窗口”**未验证**，先实测再依赖。
2. 初始化包里与凭据、会话相关的部分**照原样复用**，不要自己另写一套，否则会和存档、账号状态冲突。
3. 日志三件套必须保留：`events.jsonl`、`patch_v50.log`、`client_out.log`。没有日志的自研壳等于不可调试。
4. 首次运行校验：`bridge_ready ≤ 2s`、`native_title_creation_error` 出现、`native_account_loaded ≈ 24s`。

| # | 检查 | 判据 |
|---|---|---|
| 1 | 界面洁净 | 用户视野内不出现任何非本壳窗口（含品牌提示、群号推广、试用提示） |

