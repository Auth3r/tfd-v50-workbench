## 判据与结果

```
test real_captured_pairs_reproduce_on_wire_bytes_exactly ... ok
test two_independent_captures_agree_on_the_322_byte_frame ... ok
test key_is_thirty_printable_ascii_bytes_and_cycles ... ok
test length_is_preserved_and_empty_body_stays_empty ... ok
test single_byte_corruption_in_body_changes_exactly_one_payload_byte ... ok
```

- `wrap(body) == 抓包原始载荷`，6 组逐字节相等；反方向 `unwrap(payload) == body` 同样成立。
- 两局独立抓包：322 B 那条 body 与 payload 完全相同（`seq=12` / `seq=19`）。
- KEY 30 字节全为可打印 ASCII，周期在第 30、60 字节处验证。
- 负对照：body 第 232 字节翻转 1 bit → payload 恰好 1 字节差异。

全仓回归：`cargo test` 19 个测试目标全绿、0 失败、退出码 0（含既有 `v50_login` / `v50_save` / `v50_codec` / 协议测试）。

## 这层的作用与边界

- **作用**：核心第一次具备"body → 线上字节"的物理能力，为 S2-c（挖断测试）做准备。
- **不做**：不写 10 字节帧头（那是 G5 的判据，等它绿了再进核心）、不解 body、不碰 `content.sealed`、不碰世界运行时。
