# 判据 · S2 零依赖双跑（A 路线验收）

---

## 1. S2 是什么

一句话：**同一份输入，我们的核心产出与 V50 外壳产出逐字节相等；然后把 V50 藏起来，我们顶上，客户端照样能握手。**

拆成三层判据，必须按顺序全绿：

| 层 | 判据 | 现在 |
|---|---|---|
| **S2-a · 报到层** | 给定 body，`wrap(body) = body XOR KEY[i%30]` 与抓包 `raw` **逐字节相等** | **已过**（8/8 配对行；见 §2） |
| **S2-b · 身体层** | 同一请求，我们的核心产出 body 与 V50 产出 body **逐字节相等** | 部分绿：proc 1 的 70→72 B 已由核心测试逐字节断言（对象方 M02 复检 3 项通过） |
| **S2-c · 挖断测试** | 把 V50 目录改名藏起，自有核心在同端口应答，真实客户端走到登录握手 | **未开始**（需要一次实机运行） |

**只有三层全绿才能说“A 通了”。** S2-a 过不等于 A 过 —— 它只证明我们抄对了这一层编码。

## 3. 由此暴露的真实缺口（比“加个 XOR”更重要）

**登录那条只有单边证据。** proc 1 的 72 B body 在日志里有、在本次抓包里没有对应的 raw；反过来，抓包里的 proc 1 又是另一次运行的。

后果：S2-b 能把登录 body 对到字节级，但 **S2-a 的登录段（body→raw）现在无法配对验证**。S2-c 挖断测试一旦走到登录握手，缺的正好是这一段。

**处置（建议下次抓帧时专门补齐）**：
- 启动时把 proc 1 的**应答 raw** 与**日志 body** 打上同一个 run id（现在靠时间戳不够稳）。
- 判据升级为：同一 run id 下，`wrap(log_body) == wire_raw`，且 `core_body == log_body`。
- 抓帧开关已在 `patch_v50.py` 的 `_wire_capture()` 里，不需要改客户端。

## 4. 核心工程要做的第一件事（等你确认再动代码）

现状：`rust/v50_login.rs` 文件头自己写着 *“does not transform a body into an outer transport payload (M01c)”* —— 也就是说报到层在自有核心里**根本没实现**，只有 body 层。

第一刀代码量很小：

1. 新增 `rust/v50_payload.rs`：`wrap(&[u8]) -> Vec<u8>` / `unwrap(&[u8]) -> Vec<u8>`，KEY 常量直接写死 30 字节。
2. 新增测试 `tests/v50_payload.rs`，用**真实配对**做夹具：4 B / 223 B / 322 B / 5 B 四组（两局各一份）。
3. 扩展现有登录测试：`encode_login_reply` → `wrap` → 与真实 raw 比（等 §3 的配对补齐后再加）。

**验收**：测试通过 + `cargo test` 全绿 + 不引入任何依赖（`[dependencies]` 保持空）。

风险：低。纯函数、无 I/O、无网络、无游戏交互。
