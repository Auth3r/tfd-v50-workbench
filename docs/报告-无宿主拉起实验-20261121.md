# 报告 · 无宿主拉起实验（第三刀）

日期：2026-11-21 · 环境：Windows 11 本机 · 客户端 Build 26722146（sha256 前缀 `a601a30d`）
结论一句话：**不启动 `TFDLauncher.exe`，客户端也能被拉起、进入登录、主动连上外部端口。启动驱动可以不由宿主承担。**

---

## 1. 实验方法

| 项 | 做法 |
|---|---|
| 拉起 | 由自研脚本外部拉起客户端进程（挂起态，尚未执行任何客户端代码） |
| 加载桥 | 在挂起态加载兼容桥 `offset_rework/old_bridge_v30_bt.js`（102,995 B），加载完成后才放行进程 |
| 接收端 | 本脚本自带一个**只接受、只记录、不应答**的本地端口（`127.0.0.1:47811` / `47813`） |
| 命令行 | `-LoginIP=127.0.0.1 -LoginPort=<端口> -log` |
| 观测 | 进程存活、桥事件流、端口是否被连接、首帧字节、窗口画面 |
| 未做的事 | 未启动宿主、未启动任何现有启动脚本、未修改仓库任何文件、无应答逻辑 |

目的不是“跑通游戏”，而是回答一个问题：**离开宿主，客户端还能不能走到发起连接这一步。**

## 3. 首帧原文（35 字节）

```
19 00 00 00  e7 ff ff ff  ff 7f  23 a2 f7 57 44 28 22 20 0f 38 00 11 24 2c 3b
65 59 5f 36  39 1e 4a a9 ee 14
```

按字节偏移观察（**以下为观察，不是定论**）：

| 偏移 | 字节 | 观察 |
|---|---|---|
| 0..3 | `19 00 00 00` | 小端 int32 = **25**，恰好等于后随载荷长度（35 − 10 = 25） |
| 4..7 | `e7 ff ff ff` | 小端 int32 = **−25**，与上一个字段数值相同、符号相反 → 疑似镜像/校验字段 |
| 8..9 | `ff 7f` | **`0x7fff`**，与已知的明文传输标记一致 |
| 10..34 | `23 a2 f7 …14` | 25 字节载荷；按登录时序推断应是登录请求（procedure 1）的请求体 |

请帧层实现方用自己的解析器验证：**第 0..3 字段是否等于载荷长度、第 4..7 是否恒为其负值**。若成立，这是一条可直接写成断言的强校验；若不成立，说明本样本的头部布局与我们此前理解不同，需要重新对齐。

## 4. 与宿主路径基线对比

| 指标 | 宿主路径（历史长稳局） | 无宿主（本实验） |
|---|---|---|
| 桥就绪 | 1.190 s | 0.74–0.98 s |
| 平台配置事件 | 4–6 s（快档） | 20.9 / 26.5 s（慢档） |
| 首次连接 | 28.99 s（首次心跳） | 24.3 / 29.5 s |
| 进程存活 | 8495 s（exit 0） | ≥60 s（实验主动关闭） |
| 画面 | 标题页可交互 | 标题/登录界面 + 登录失败弹窗 |

**关键差异**：本实验落在“慢档”（平台配置 20.9 s），按旧判据属于“必黑屏区间”，**但没有黑屏**。原因见下。

---

## 5. 由此改写的一条旧判断（重要）

旧判断：平台配置落在 20–30 s 就黑屏，`born + 22 s` 门控是放大器。

本次观察：**桥在 0.74–0.98 s 就加载完成（早于客户端执行任何代码），慢档也不黑。**

因此真正决定黑屏与否的不是“绝对秒数”，而是**桥加载相对客户端初始化的先后关系**。只要桥进得足够早，慢启动也不影响；反之即使快档，桥晚进也会掉进门控空窗。

对工程的直接影响：**拉起流程必须“先挂起 → 先加载桥 → 再放行”**，不能“先跑起来再挂桥”。这条应写进任何自研启动器的实现约束。

---

## 6. 失败点定性

弹出的「游戏登录失败 [LE:13]」发生在**客户端已经发出登录请求、但没人应答之后**。

也就是说：

- 失败原因不是启动链缺件；
- 失败原因不是桥没生效（桥事件流完整）；
- 失败原因就是**接收端是哑端口，没有回任何字节**。

这属于内容层/服务端的工作，不属于启动驱动。

---

## 7. 这份材料对帧层实现的用途

1. **真实样本**：首个业务帧的完整字节，可用来校验解析器。
2. **头部断言**：偏移 0..3 与 4..7 的“长度/负长度”关系，可写成单元测试。
3. **时序基线**：桥就绪 < 1 s、首连 24–30 s，可用于判断自己的启动器是否“进得太晚”。
4. **失败样本**：无应答时客户端行为（弹窗 + 不自动重试），可用于设计重试与容错。

---

## 8. 未覆盖的范围

- 本实验**没有应答任何帧**，因此无法判定“正确应答后能否进入下一阶段”；
- 没有验证过长时间稳定性（宿主路径有 8495 s 记录，无宿主路径只观测到 60 s）；
- 没有验证多角色、多存档、地图切换等场景；
- 端口固定为测试值，正式实现需纳入统一配置。
